# 地上側ATC 基本仕様

状態：地上工程1〜6と車上ORP保持・開扉時解除の実装を反映。未決事項は該当機能の実装前に確定する。

今回のリファクタリングで確定した処理順・工程ごとのInput・State・Outputと、[issue #67](https://github.com/neko3141592/Nakatetsu/issues/67)の修正方針は、[地上ATC 全体処理仕様](TrackAtcProcessingFlow.md)に定める。今回の地上工程1〜6は、進路未設定時も全Edgeを探索対象とし、Interlockingでは両方向に有効な単一Edge・`None`の停止電文を生成する。車上側のORP保持・開扉時解除も実装済みである。

## 1. 対象

- 初期版は `Block` と `Interlocking` を対象とする（ユーザー回答で確定）。
- `Yard` の運転制御は後回しとする。
- 列車追跡、編成ID・列番の対応付けはCTC側の責務とし、地上ATCへ組み込まない（ユーザー回答で確定）。
- 提案：初期版の探索はYard区間の入口で終了し、その先の進行を許可しない。
- 静的な線路情報はコンパイル済みの `TrackAtcGraphAsset.Definition` を使用する。
- 地上側の経路探索・電文生成・軌道回路への配信を実装する。車上側の距離計算・制動パターン生成は別途実装する。

### 現在の実装範囲

Context・工程別State・Logicは`Assets/Nakatetsu/Track/Atc/Scripts`の`Nakatetsu.Track.Atc`名前空間に実装する。既存の`Nakatetsu.Track.Atc.TrackAtcController`コンポーネントが、新しいContextへ入力を集め、新しい親Logicを呼び、Outputを軌道回路へ配信する。

- 毎tick、入力をスナップショットし、ATC Graphと入力を確認して探索用辞書を初期化する。全Edgeを起点としてEdge・方向別に計算し、探索済みのEdgeを別の起点から通過したことを理由に、そのEdge自身の計算を省略しない。
- 初期化済みの連動で確認できた未設定は`RoutesById`へ`IsRouteSet = false`で登録し、入力未取得の未登録・`null`と区別する。設定中の状態を取得できた場合は`IsRouteSet = true`とし、進行許可・開通・鎖錠・取消・防護方式を取り込む。
- Blockは定義方向、Interlockingは両方向に結果を用意する。Interlockingの静的進路が一方向だけでも、反対方向の単一Edge・`None`停止結果を用意する。設定済み進路に沿う延伸には、静的進路の定義方向と使用条件の一致を要求する。
- 進路内を起点にする探索では、採用済み進路とそのEdgeのindexを引き継ぐ。先頭Edgeでも `ProceedAllowed` の低下だけでは探索を打ち切らない。末尾Edgeも起点にでき、次回路の占有で経路が切れている場合も、そのEdgeの停止限界を送る。
- 探索結果はStateへ次EdgeのID・方向、起点ごとの停止限界・終了結果として保存する。Output生成時に次Edge参照を辿り、最初の起点の停止限界で打ち切ってEdge列を組み立てる。
- 防護方式は、`terminalAtcRouteId`から静的ATC進路定義の`interlockingRouteId`を解決し、その連動進路Inputの`OverrunMode`を採用する。停止限界に終端進路が対応しない正常停止は`None`とし、必要な入力欠落や不正な方式と区別する。
- `Output.telegrams` は軌道回路IDをキーにする。各電文は発行時刻・有効フラグと、`(atcEdgeId, direction)` ごとの経路情報を持つ。
- 経路情報は残りのEdge列・停止限界のEdge ID・過走防護方式を持つ。停止限界は終端Edgeの進行方向の退出端とし、距離を地上で計算しない。
- 探索や方式の確定に失敗した軌道回路は無効とし、同じ更新内の別経路の成功では有効に戻さない。必要な入力欠落・方向不明・接続不整合・探索上限到達・未対応のYardは正常停止と区別する。Graphを使用できなければ送信対象を空にし、時刻が不正なら全送信対象を無効とする。無効電文に部分的な成功経路は含めない。
- アプリの更新順は列車・占有・連動・地上ATCとし、生成した電文は次tickの車上制御で利用する。発行時刻は共通のシミュレーション時計から取得する。
- 配信時に軌道回路の電文を置き換え、前回だけ存在した電文は残さない。ATCの無効化時にも電文を取り下げる。
- シーンではApplicationのATC参照と、ATC ControllerのGraph・軌道回路・連動の参照を設定する。時計はApplicationからATCへ設定する。

旧実装の「未設定の連動Edgeを単独探索しない」「方向を含めず探索済みを管理する」「探索結果を直接Outputへ保存する」構成は、新しい工程別Stateと全Edge・方向別計算へ置き換える。

## 2. 既存実装と接続上の注意

- ATC GraphはEdgeの接続・長さ・所属軌道回路・制御方式・速度制限・勾配と、順序付きの連動進路を持つ。
- `Block` の通行方向はEdgeに保持される。連動進路の方向は順序付きEdge列から求める。
- Y字型回路の複数ATC Edgeは同じ軌道回路IDを共有する。占有だけではどの枝に列車がいるか決まらない。
- 現在の連動は、進路内への列車進入によって `ProceedAllowed` をfalseにする。
- `RouteLocked` は転換待ちや取消後にも成立し得るため、単独で進行許可とみなさない。
- 進路への新規進入の可否と、進路内を起点に前方へ辿れる条件を分けて設計する。地上ATC内に列車ID別の進入履歴を持つことは前提にしない。
- 占有判定はBlock・Interlocking共通とし、異なる回路へ進む際に次回路の占有を照査する（第6節）。

## 4. 地上・車上の責務

地上→車上の運転情報は、停止限界と進路（進行順のATC Edge列）、その停止限界に対する接近時の制限条件とする。過走防護方式に応じた車上制御のため、従来の停止限界・Edge列に制限条件を追加する。

- 地上側は通行可能な経路と停止限界を決定する。速度制限・勾配の配列や許容速度は送らない。
- 停止限界は境界位置をそのまま送る。地上側で停止余裕を差し引かず、車上側がパターン計算時に適用する。
- 車上側は同じATC Graphから、その経路に沿った速度制限・勾配を取得し、ブレーキパターンを生成する。
- 地上側の計算結果は `(atcEdgeId, direction)` をキーに保持する。車上は現在位置・進行方向に対応する結果を受け取る。列車ごとの要求・応答や、列車ID別の計算結果は持たない。
- 探索結果には各キーの次Edge ID・方向と、起点ごとの停止限界・終了結果を保存する。起点ごとの全Edge列はOutput生成時に次Edge参照から組み立て、最初の起点の停止限界で打ち切る。
- 提案：車上位置は車上の推定位置を用い、ATC Graphの物理Track対応付け情報から実位置を逆引きしない。
- 先頭Edgeの方向は計算結果のキーで区別し、以降は順序付きEdge列の接続から求める。停止限界は終端Edgeの進行方向の退出端として表す。地上・車上でGraphを一致させる方法の詳細は未決。

### 過走防護方式と車上の停止目標（確定）

連動進路の末尾まで探索し、後続進路にもBlockにも進めない場合は、`terminalAtcRouteId`を静的ATC進路定義で解決し、その`interlockingRouteId`に対応する連動進路Inputの`OverrunMode`を確認する。その停止限界に対する制限条件を、各起点に対応する地上電文へ反映する。

| 終端進路の過走防護 | 車上側の扱い |
| --- | --- |
| `None`（過走防護定義なし） | 通常パターンを使用する。常用は停止限界の100m手前、非常は5m手前を停止目標にする |
| `Normal` | Noneと同じ通常パターンを使用する。常用は100m手前、非常は5m手前を停止目標にする |
| `Restricted` | ORPを適用する。常用を停止限界の100m以上手前で25km/hまで降下させ、その上限を終端まで維持する。停止への降下は非常パターンが担当し、5m手前を停止目標にする |

- 本シミュレータでは、`overrunProtection == null` を `None` とする。
- 定義が存在し、`common` と `normalAdditional` の設備リストがすべて空の場合は、「追加で確保する設備がなくても通常扱いでよい」という明示的な設定とする。ほかの成立条件を満たせば `Normal` とし、車上は通常パターンを使用する。
- 空のリストと、定義内の `common`・`normalAdditional`・設備リスト自体の `null` は区別する。後者は定義不備であり、Normalとして扱わない。
- 地上は停止限界の境界位置をそのまま送り、停止余裕を差し引かない。車上が制限条件に応じて停止目標を求める。
- 通常パターンの100m・5mは停止目標の手前補正量であり、ブレーキ開始位置ではない。補正位置が前のEdgeにまたがる場合も、走行経路に沿って距離を求める。Noneの100mを常用の100mへ重複して加算しない。
- ORPは`Restricted`使用時だけ適用する。100m以上手前という条件は、常用の25km/h到達位置に対する条件とする。非常の停止目標は停止限界の5m手前で、目標以降の許容速度は0m/sとする。
- ORPの常用は、25km/h到達後もその上限を終端まで維持する。常設速度制限がこれより低ければ、その制限を優先する。停止への降下は非常パターンで行う。
- 進路途中の占有・取消による探索終了は、進路末尾への到達と区別し、停止限界に対応する終端進路の方式を使用する。進路未設定で終端進路が対応しない正常停止の方式は、今回の修正で`None`とする。補正後の目標を既に通過している場合の処理など、車上の詳細は車上側の仕様で定める。

今回の地上修正では、Interlockingの進路解放後に進路未設定と確認できる場合も、両方向に起点Edgeだけの経路と`None`を有効な停止電文として送る。停止限界はそれぞれの方向の起点Edge退出端とする。入力欠落や不正な方式を`None`へ置き換えない。以下の車上側のORP保持・開扉時解除を、実際に使用する方式へ反映している。

本進路が設定されたまま過走防護だけが解放される場合の送信方式は、進路未設定時とは別の条件として確認する。

車上の計算方法・停止目標・未決事項の詳細は、[車上ATC ブレーキパターン仕様](../../Train/Atc/TrainAtcBrakePatternSpecification.md)に記載する。

### 車上ATCのORP保持・開扉後の常用保持と転動防止Br（確定）

以下のORP保持・解除は、車上の`TrainAtcProtectionModeLogic`・`TrainAtcProtectionModeState`と開扉操作番号の入力に実装している。

車上の防護方式を決める`TrainAtcProtectionModeLogic`でORP保持・解除を扱う。専用の駅停車待ち状態や、現示だけを0へ固定する処理は追加せず、開扉後は既存の`None`パターンと常用停止保持を使用する。

- 有効な`Restricted`を採用した時点で、停止限界のEdge IDと、その終端Edge上の進行方向を`TrainAtcProtectionModeState`へ保存する。
- `None`または`Normal`を受信しても、ORP保持中で停止限界・終端方向が同じなら、その方式を保持する。進路解放後に進路未設定となり、単一Edge・`None`を受信した場合も同じ規則を適用する。今回の経路は採用し、保持した方式でパターンを生成する。
- 停止限界または終端方向が変わった場合は、以前の保持を解除して今回の指定方式を採用する。現在Edgeや経路の先頭の変化だけでは解除しない。
- 新しい開扉操作番号で以前のORP保持を解除し、今回受信している方式を採用する。停車速度や全閉状態は解除条件にしない。進路未設定時の`None`受信中なら、通常パターンを生成する。開扉状態が続くことだけで毎tick解除・パターン消去を繰り返さない。
- 開扉操作を確認したtickでは再保持せず、次tick以降に有効な`Restricted`を受信した場合は、同じ終点・方向でもORPへ戻ってよい。再採用を禁止する状態は設けず、解放済み設備に対する古い保持が残ることを防ぐ。
- 停止限界の100m以内で停車している場合は、`None`の常用パターンが0となり、既存の常用最大の停止保持が働く。閉扉だけではこの保持を解除しない。
- 後続進路成立で停止限界が延び、新しいパターンの緩解条件を満たした場合に、全閉確認後の通常のブレーキ判定で緩解する。進路成立だけで無条件に緩解しない。
- 開扉中の転動防止Brは独立して継続する。進路成立でパターンが変わっても、全閉未確認の間は常用最大を要求する。
- 無信号・無効電文・入力不正は既存の受信判定に従い、ORP保持情報だけで使用可能にしない。開扉操作はキー切・入力不正中も処理する。無信号猶予中の開扉では保持対象を解除し、既存パターンと方式を維持した後、次の有効なNone受信時にNoneを採用する。

100m以内という条件は、受信した停止限界に対する停車位置の条件である。地上から固定の0速度を送ったり、すべての停車位置で一律に0現示を保証したりする方式にはしない。

保持・解除に必要な車上Input・Stateと確認シナリオは、[地上ATC 全体処理仕様](TrackAtcProcessingFlow.md)の第5節に記載する。地上側には列車追跡、列車ID別の出力、開扉操作やORP保持の状態を追加しない。

## 5. 連動から受け取る情報

ユーザー回答により、以下の2種類を区別する。

1. 新規進入の許可：その進路に従って先へ探索を延ばしてよいか。既存の `ProceedAllowed` に対応する。後続進路の先頭Edgeが前進路と共有される場合、前進路による共有Edge終端までの進行を妨げない。
2. 開通・鎖錠中の進路：進路内を起点とする探索で、現在確保されている枝と経路を特定するための情報。

通常の列車進入による `ProceedAllowed == false` だけを理由に、進路内を起点とする探索を終了しない。一方、開通・鎖錠中であることだけを理由に、新しい列車が進路入口を越えられるようにしない。取消した進路による探索継続は認めないが、共有Edgeに別の有効な進路がある場合は、その進路に従って継続できる。

開通状態は連動側の `PathEstablished` で受け取る。本進路の鎖錠、本進路用転轍機の実位置、保持中の過走防護の成立・空き・転轍機実位置を照査した値であり、`RouteLocked` 単独で代用しない。本進路への通常の進入では `PathEstablished` を維持し、新規進入用の `ProceedAllowed` だけを下げる。過走防護が正規の条件で解錠された後は、解放済み設備を開通照査の対象から外す。

進路設定中の状態は`IsRouteSet = true`、初期化済み連動で確認できた未設定は`IsRouteSet = false`としてInputへ登録する。連動が未初期化・参照不可などで確認できない場合は、未設定として登録せず入力未取得とする。`ProceedAllowed == false`だけでは未設定と判断しない。

新規進入には `IsRouteSet && ProceedAllowed && PathEstablished && !CancelPending` を要求する。進路内からの探索では `IsRouteSet && PathEstablished && RouteLocked && !CancelPending` を使用する。過走防護方式は `OverrunMode` として受け取り、地上ATCが停止限界の制限条件を車上へ伝える。Normal・Noneの通常パターンとRestrictedのORPは第4節に従う。

`TrackAtcPathLogic`は、成立・鎖錠中の進路内を起点とするとき、採用した進路とindexを探索中に引き継ぐ。これにより、21T共通部が進路の先頭Edgeであっても、進入後の継続として扱う。Blockからの新規進入や、進路末尾から別進路へ切り替える際には新規進入許可を照査する。

Blockから新規進入して先頭Edgeへ到達した後は、同じ進路の継続条件として`RouteLocked`も要求する。前進路の終端と後続進路の先頭が共有Edgeであれば、既に共有Edgeへ到達しているため、後続進路の次Edgeへ延ばす前に、新規進入条件と進路内継続条件の両方を照査する。

### 進路取消（確定）

- 進路への進入後も取消を受け付ける。取消を受けた進路は、新規進入を許可せず、進路内にも停止を指示する。
- 取消による停止と鎖錠を分離する。取消を理由に直ちに解錠せず、列車を保護する鎖錠を維持する。解錠は別の条件として扱う。
- 地上ATCは `ProceedAllowed` の低下だけから取消を推測せず、連動から取消状態（現実装の `CancelPending`）も受け取る。
- 取消後も確保された経路の情報は保持するが、その経路を走り続けてよいという許可には使わない。
- この決定により、既存実装計画の「進入後は任意取消を受け付けない」という初期制限を変更する。
- 未進入側へは進路入口を停止限界として示す。
- 取消対象進路内のEdgeを起点とし、ほかの有効な進路がない場合、経路を起点Edgeの1本だけとし、停止限界をそのEdgeの進行方向の退出端とする（ユーザー回答Bで確定）。取消した進路を使って次Edgeへ探索を延ばさない。
- 共有Edgeに別の有効な進路があれば、その進路に従って継続できる。例えば1RT上で場内進路が取消済みでも、出発進路に進行許可があれば22Tへ進める（ユーザー回答で確定）。別回路への遷移時の占有判定は引き続き適用する。
- A→B向けの退出端はNode B、B→A向けの退出端はNode A。別の有効な進路がない場合、同一軌道回路に属する次Edgeがあっても、この取消時の終了条件を優先する。
- 地上はEdge退出端をそのまま送り、車上が停止余裕を適用する。進入端を送って一律に停止限界超過として扱う方式は採用しない。
- 取消指示後の境界超過・位置補正時に、車上が新しいEdgeの出力だけで停止限界を前方へ更新し続けないための扱いは、車上側との接続仕様で整理する。地上側に列車追跡を追加する前提にはしない。

### 進行範囲の重複と鎖錠範囲（確定）

隣接する進路は、前進路の末尾Edgeと後続進路の先頭Edgeを1本共有する。進行可能範囲は共有するが、その接続のために進路鎖錠の範囲を重ねない。別の許可境界を追加する案は採用しない。

| 進路 | 進行可能範囲（回路単位の略記） | 鎖錠する転轍機 |
| --- | --- | --- |
| 場内：21T → 1RT | 21T・1RTを通り、1RT終端まで | 21 |
| 出発：1RT → 22T | 共有する1RTから22Tへ進み、22T終端まで | 22 |

21T・22Tは複数ATC Edgeから成るため、実際の進行可能範囲は、選択した枝に沿う順序付きEdge列で表す。上記の接続ではホームEdgeである1RTが1本共有される。本線の2RT側も同様。

- 場内のみ設定：経路を1RT終端まで返す。出発進路の未設定を理由に1RTへの進入を止めない。
- 場内・出発とも設定：1RTを重複追加せず、後続進路の2本目のEdgeから探索を継続する。接続方向も一致させる。
- 1RTを起点とし出発進路が未設定：1RT自身を返し、各方向の終端を停止限界にする。前の場内進路が既に解放され、終端進路が対応しなければ、両方向に単一Edge・`None`を返す。
- 一般に、先へ進むための進路が未設定なら、探索を延ばさず現在Edgeの終端で止める。
- 進行可能範囲に含まれることを、そのまま鎖錠対象であることへ読み替えない。占有による停止判定は引き続き第6節を適用する。

NtLine Assetの場内進路は、設定照査・予約用の`routeClearTrackCircuitIds`に入口区間とホーム回路を含め、後端通過による解錠用の`routeReleaseTrackCircuitIds`には入口区間だけを指定する。ホーム在線中でも入口区間を後端が抜ければ本進路を解錠できる。ATCの進行可能範囲は従来どおりホーム終端までとする。連動の詳細は[連動装置の全体処理仕様](../Interlocking/TrackInterlockingProcessingFlow.md)に従う。

## 6. 占有による探索終了条件（確定）

旧実装の連動区間側の方式を採用し、Blockにも同じ判定を適用することをユーザーが決定した。

1. 探索起点となる現在Edge自身の占有を理由に探索を打ち切らない。
2. 現在Edgeと次Edgeの `trackCircuitId` が同じなら、占有を理由にその遷移を禁止しない。
3. 両者の回路IDが異なり、次回路が占有なら、次Edgeを経路へ追加せず、その入口境界を停止限界として送る。手前に停止する余裕距離は車上側で適用する。
4. 異なる回路が空いていれば、方向・連動進路などの条件を満たす場合に探索を続ける。

同一回路という理由で分岐の両枝へ進むことは認めない。Interlockingでは特定された開通経路に従い、新規進入の許可が必要な境界ではその条件も照査する。

この判定に列車IDや自列車の識別は使わない。いったん別回路へ出てから起点と同じ回路へ戻る遷移も、異なる回路間の遷移として占有を照査する。「起点回路IDなら経路中のどこでも無視する」方式にはしない。

| 状況 | 期待する扱い |
| --- | --- |
| 占有中の20Tを起点に、空きの21Tへ進む | 20T自身の占有では止めない。21Tへの進路許可を別途照査 |
| 占有中の21T共通部から同じ21Tの本線側へ進む | 確保された本線進路に従って継続 |
| 21Tから占有中の2RTへ進む | 2RT入口を停止限界の基準位置とする |
| 1つのBlock回路が複数ATC Edgeに分割されている | 同じ回路が続く範囲は占有で打ち切らない |

同一回路内の複数列車を個別に識別・防護する機能は含めない。初期対象外の入換・併結などをこの方式だけで扱わない。回路情報の欠落は「既知の回路が占有」と区別して仕様化する必要があり、本節の例外で入力欠落を通行許可へ読み替えない。

## 7. 旧プロジェクトの占有判定（調査結果）

`/Users/yudai/TD-ATC/Assets/Scripts/Track/Safety/Atc/Ground/AtcGroundController.cs` を読み取り確認した。占有判定の採用範囲は第6節に記載する。それ以外の旧実装を一括採用する決定ではない。

- 全ATC Edgeについて次Edgeを計算し、そのリンク列から送信用の経路を復元する（226行、109行）。列車IDを探索入力には使わない。
- 現在Edge自身の占有を理由に探索を打ち切る判定はない。
- `Block` からは次Edgeの `blockId` の占有を調べる。同一回路かどうかの例外はない（302行）。
- 連動区間からは、現在と次の `blockId` が異なる場合だけ次回路の占有で止める。同一回路内の複数Edgeは、特定された進路に沿って継続する（387行）。
- 外側のBlockから進路を探す場合は `Established` のみ、連動区間内の経路特定では `Established` または `Occupied` を認める（310行、331行、743行）。後続進路への連鎖でも `Occupied` を許容する実装のため、この部分をそのまま新仕様の新規進入許可へ読み替えない。
- 送信は軌道回路IDでまとめ、同じ回路に属するATC Edgeごとの経路を格納する（138行）。

旧実装の基本は「次の回路へ移るときに占有を照査する」。新仕様では、旧Block側にも同一回路内の遷移を許す条件を適用して統一する。
