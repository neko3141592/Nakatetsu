## 実装

Applicationが全Trainの自動更新を止め、初期化完了後に一定幅のStepを実行する。全Trainの更新後にtick番号を進め、開始時刻と経過時間から世界時計を求める。停止・再開・早送り・停止中の手動1tickに対応する。1フレーム100tickを初期上限とし、端数と未処理時間を持ち越す。

Applicationのasmdefを直下に置き、SimulationとDebugを同じAssemblyに含めた。UnityのApplication参照は名前空間衝突を避けるため明示した。

## 確認結果と限界

- 本人より再生倍率の実装・動作確認済みとの報告あり。デバッグUIについても表示・動作の確認報告を受けた。
- 一時的な.NET検証プログラムで、実ControllerソースとUnity／Trainの代替実装を使い、初期化待ち、端数保持、停止・再開、停止時間の非加算、実行上限と繰越し、手動tick、2列車の呼出回数と時計の一致を確認した。
- 同じ検証で開始時刻、2倍速、日跨ぎ、開始後に開始時刻とtick幅が変わらないことを確認した。
- デバッグUIと時計ControllerはローカルUnity DLLを参照する簡易コンパイルでエラー0件。手元のTrain DLLに作業途中の同名クラスが含まれる警告があった。その作業途中ソースはPRに含めない。
- 上記の簡易検証はUnityのPlayModeテストではない。全機器の状態を比較する通常／早送り／手動実行の等価性試験、全既存テストの再実行、配布ビルドの確認は今回実施していない。

## snapshot対象Stateと所有者

保存・復元本体はW5で実装する。以下を起点に、その時点の追加機能も含めて次tickへ影響する値を再監査する。

| 所有者 | 保存対象／復元時に決める値 |
| --- | --- |
| ApplicationSimulationController | 開始時刻、固定tick幅、完了tick数。端数・未処理時間、停止状態、倍率は実行セッションとして保持するか、tick境界で再開用に初期化するかをW5で明示する |
| TrainPhysicsController / TrainPhysicsContext | 符号付き速度・加速度などの物理State |
| VVVF・Motor・Brakeの各Context／Controller | モーター・インバーターの応答状態、BC圧など、次tickの力に影響する内部状態 |
| DoorのController／Simulation | 開閉状態、進行位置、動作タイマー・指令保持状態 |
| Load・運転操作の各Context | 荷重状態、マスコン・スイッチの位置と操作状態 |
| EB / EbDeviceContext | 無操作経過時間、前回マスコン状態、その有効フラグ |
| TIMS制御・通信／Bus・速度測定 | 非常保持、通信状態、次tickが読む前tick値、センサーの継続状態 |
| Track・運行（後続実装） | 永続Train ID、Edge位置、編成向き、通過履歴、占有・進路鎖錠・ダイヤ進捗 |

Unityオブジェクト参照や描画状態をそのまま保存しない。機器参照・作業用キャッシュは生成と接続で再構築する。
